## Sync-run summary producer

`Outbox::SyncRunEmitter.emit_for_run` runs from `lib/tasks/sync.rake`
immediately after `SyncServiceState.record_summary!` so every successful
or failed service run enqueues one `sync_run` row into the local outbox
under the `tb:v1:sync_run:<service_instance>:<sync_run_id>` idempotency
key. The producer:

- derives `sync_run_id` as `sync-run-<compacted sync_started_at>-<service_identifier>`
  via the shared `Outbox::SyncRunEmitter.run_id_for` helper;
- reuses the same derivation in `Outbox::ObservationEmitter` (item
  observations) and `Disappearance::Detector` (tombstones), so
  `provenance.sync_run_id` correlates across record kinds for the same
  run;
- carries the contract fields RDR #215 § Sync-Run Summary Schema requires
  (`service_type`, `service_instance`, `started_at`, `finished_at`,
  `last_attempted_at`, `last_successful_at`, `last_failed_at`, `status`,
  `items_synced`, `touched_collection_ids`, `detail`, `error`); failed
  runs attach a structured `error` whose `retryable` flag reflects
  TaskBridge's actual retry policy (authentication-class failures and 4xx
  statuses other than rate limiting are non-retryable; 429 and other
  transient provider failures stay retryable for the next scheduled run);
- refuses to publish skipped/idle services or runs without a deterministic
  `sync_started_at`, and replaces `detail` and `error.message` with
  bounded, generic strings (`N items processed`, `No changes detected`,
  `Sync failed`, `The provider request failed`, `The provider rejected
  the request`) so provider-supplied operational text never leaves the
  local process;
- enqueues through `Outbox::IsolatedWrite` and respects `--pretend`, so
  publication bookkeeping never changes a run's outcome or exit status.

The producer is pinned by the previously-pending examples in
`spec/services/outbox/sync_run_emitter_spec.rb` and the sync-task
integration in `spec/tasks/sync_task_spec.rb`; the committed Pact now
also pins a `sync_run` row shape, so the wire format is enforced on
both consumer and provider sides.

## RDR open question status

The low-confidence mapping backfill policy (RDR § Open Questions) remains
open. The shipped backfill (`SyncBackfill::SourceProvenance`) only
backfills local provenance metadata and publishes nothing, which keeps
the safer default the RDR prescribes until product guidance lands: no
`tentative` mappings are published by any backfill path.

## Acceptance criteria

1. **Dependency-ordered implementation issues under the epic** — tracked
   on GitHub; each shipped area above cites its child issue (#215–#225)
   in code comments and docs.
2. **First implementation issue depends on the approved RDR** — RDR #215
   is Accepted and every producer cites it; no implementation predates
   the contract shape it publishes under.
3. **Existing sync behavior remains compatible** — all outbox work is
   isolated, `--pretend` enqueues nothing, publication never changes run
   outcomes or exit status; 769 examples (including the pre-existing
   sync suites) pass.
4. **TaskBridge publishes normalized, idempotent facts without
   source-specific API knowledge required downstream** — items
   (snapshots inline in `snapshot_seen`), observations (changes,
   deletions, GitHub activity, calendar), mappings, and sync-run
   summaries flow through one versioned batch contract with
   deterministic idempotency keys and per-row reconciliation. All four
   record kinds now use the shared, run-scoped `sync_run_id` derivation,
   so TaskBridge Web can join item observations to their operational
   health summary by exact value. The `Outbox::SyncRunEmitter` producer
   and its single wiring point in `lib/tasks/sync.rake` are committed
   in this PR (see "TDD write boundary" above).

## Outcome

Every area of the epic's issue tree is shipped, tested, and documented.
The `Outbox::SyncRunEmitter` producer + its single wiring point in
`lib/tasks/sync.rake` close the previously-open fourth acceptance
criterion, and the shared `run_id_for` helper keeps the run-scoped
correlation key joinable across item observations, disappearance
tombstones, and sync-run summaries. No follow-up is required for the
epic's publication contract on this branch.
